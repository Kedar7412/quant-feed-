# 3D Graph Visualization and Live News Pipeline Overhaul

This change replaces the 2D force graph with a Three.js-powered 3D network (react-force-graph-3d), adds glassmorphism + framer-motion animations across all UI components, and overhauls the news pipeline to fetch live data from 22 RSS feeds plus GNews and NewsData.io APIs before falling back to mock data. The approach is sound: parallel fetching with allSettled, a 10-second timeout guard on the combined fetch, title-based deduplication, and a 30-minute throttle to avoid hitting API rate limits on every page load.

Watch for: API keys leaked in fetch URLs if server logs are exposed (confirmed). Unbounded article accumulation in `/tmp/articles.json` with no eviction (confirmed). Three.js scene objects may not get lighting if the dynamic import resolves after the mount effect fires (likely). Deduplication only works within a single fetch, not across fetches — cross-fetch duplicates accumulate in the store (confirmed).

**Verdict**: APPROVED

## High-level view

The 3D graph renders custom Three.js sphere meshes with emissive glow and particle-animated links inside a ForceGraph3D wrapper. Camera auto-rotates and pauses on interaction with a 5-second resume timeout. The scene setup effect runs once on mount with an empty dependency array — if the dynamic import hasn't resolved when the effect fires, it silently skips and the scene has no custom lighting or star background.

The news pipeline introduces `fetchLiveNews()` which races RSS + API fetches against a 10-second timeout, deduplicates by normalized-title word overlap (>80% match), and sorts newest-first. The `/api/news` route calls this on every GET unless a fetch happened within the last 30 minutes. GNews and NewsData integrations are behind optional env vars and return empty arrays when keys are absent.

The store layer writes to `/tmp/quant-feed-data/` on Vercel. Articles are merged by ID but never evicted, meaning the JSON file grows without bound within a warm serverless instance. On cold starts `/tmp` resets, so the first request always triggers a full live fetch (~10 seconds worst case) before the page can respond.

<details>
<summary>Issues (5)</summary>

1. **API keys in fetch URLs** — GNews and NewsData API keys are interpolated directly into URL strings. The catch blocks call `console.error("GNews fetch error:", error)` which for network errors typically includes the URL. Sanitize URLs before logging or strip query params from error messages.
2. **Unbounded article store growth** — `saveArticles` always appends/merges, never evicts old entries. IDs are `Date.now()` + random, so the same article fetched 30 minutes apart gets a new ID and appends. Add a max-article cap (e.g. 500) with oldest-first eviction.
3. **Cross-fetch deduplication gap** — Title-based dedup only runs within a single `fetchLiveNews()` call. The store merges by ID, so articles with slightly different titles from the same source accumulate across fetches. Apply title-similarity dedup at the store level too.
4. **Three.js object disposal gap** — `nodeThreeObject` creates two geometries and two materials per node. If react-force-graph-3d doesn't dispose old objects when `graphData` changes (e.g. category filter toggle), these leak GPU memory. Verify the library's disposal behavior on data updates.
5. **No staleness signal to the user** — When live fetch fails silently and mock data is served, nothing in the UI indicates the data is stale/mock. Users may believe they're seeing live data when they're seeing hardcoded articles from `daysAgo()`.

## API key exposure in URL strings

Both `fetchFromGNews` and `fetchFromNewsData` embed secrets directly in the URL query string:

```typescript
`https://gnews.io/api/v4/top-headlines?...&token=${apiKey}`
`https://newsdata.io/api/1/latest?...&apikey=${apiKey}`
```

These APIs require query-param auth (no header alternative), so the risk is specifically about server-side logging. The catch blocks call `console.error("GNews fetch error:", error)` which for network errors typically includes the request URL. On Vercel, these logs are persisted and visible in the dashboard. Confidence: **confirmed**.

Mitigation: wrap fetch calls to sanitize URLs from error objects before logging.

## Unbounded article accumulation

`saveArticles` in `store.ts` reads the full article list from `/tmp`, merges new articles by ID, and writes back:

```typescript
export function saveArticles(newArticles: NewsArticle[]): void {
  const articles = getArticles();
  for (const article of newArticles) {
    const existingIndex = articles.findIndex((a) => a.id === article.id);
    if (existingIndex >= 0) {
      articles[existingIndex] = article;
    } else {
      articles.push(article);
    }
  }
  writeJsonFile("articles.json", articles);
}
```

IDs are generated with `Date.now()` + random suffix, so the same real-world article fetched in two different 30-minute windows gets two different IDs and always appends. The title-based dedup in `fetcher.ts` prevents duplicates *within a single fetch*, but not across fetches to the store. A warm instance serving traffic for hours will accumulate thousands of articles, with each `getArticles()` call reading and parsing the full JSON. Confidence: **confirmed**.

## Three.js scene setup race condition

```typescript
useEffect(() => {
  if (!graphRef.current) return;
  const scene = graphRef.current.scene();
  // ... add lights, stars ...
  return () => { /* cleanup */ };
}, []);
```

The empty dependency array means this fires once after mount. `graphRef.current` is set by react-force-graph-3d's dynamic import — if the import hasn't resolved when the effect fires, the early return means no lights, no star background, no retry. The result is a fully functional but unlit graph (nodes would still render via their emissive material, but the scene would lack ambient/point lighting and the star particle effect). Confidence: **likely** — depends on dynamic import timing relative to React's commit phase.

## Cold-start latency

On Vercel cold starts, `/tmp` is empty. The `/api/news` route will:
1. Find no articles and no timestamp
2. Call `fetchLiveNews()` — fetching from 22 RSS feeds + 2 APIs in parallel
3. Race against the 10-second timeout
4. Only then respond to the client

The `/api/graph` route compounds this by also calling `extractRelationships()` on the fetched articles. Users hitting the site after inactivity will see their loading spinner for up to 10 seconds on first page load. Confidence: **confirmed** — the code path is explicit in both route handlers.
