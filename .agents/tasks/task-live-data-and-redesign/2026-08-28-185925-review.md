# Live data pipeline and premium charcoal dashboard redesign

Three commits replace the broken /tmp-gated fetch throttle with a serverless-safe in-process cache (5-min TTL), add Google News RSS as the primary reliable source, make mock-data timestamps relative, and redesign the entire UI from indigo/glass to a charcoal-panel + lime/emerald accent system with a narrow icon sidebar and top bar. The result is a dashboard that reliably displays current-dated news on Vercel (no /tmp dependency for freshness) and presents it in a dark analytics aesthetic. Watch for: the top-bar search input is decorative (no wiring to any filter logic) [confirmed]; the in-process cache is instance-local, so Vercel's multi-instance scaling means every cold instance still hammers feeds independently [likely]; and the `today` memo in TopBar has an empty dependency array, producing a stale date if the tab stays open past midnight [confirmed].

**Verdict**: APPROVED

## High-level view

The data freshness fix is architecturally sound for the stated serverless constraint. The old 30-minute /tmp timestamp gate was fundamentally broken because /tmp does not survive cold starts on Vercel; replacing it with a module-scope memo with a 5-minute TTL and concurrent-fetch deduplication is the correct lightweight alternative. The fallback cascade (live → /tmp cache → sample mock) is cleanly ordered and correctly labelled for the DataSourceBadge.

Google News RSS with the `when:1d` operator guarantees current-dated items regardless of whether individual publisher feeds are healthy. The 7-day recency filter with a "keep newest N" floor prevents an empty response on slow news days while still cutting stale content.

The UI redesign is a wholesale colour/structure swap (indigo → lime/emerald, glass blur → opaque charcoal panels, full sidebar → narrow icon rail + top bar). It is consistently applied across every page and component. The one gap worth calling out is the non-functional top-bar search: it renders an input with no `onChange` handler or state wiring, so it cannot filter anything.

<details>
<summary>Issues (4)</summary>

1. **Top-bar search is decorative** — the `<input>` in `TopBar.tsx` has no state, no onChange, and no routing to any filter/query logic. Either wire it to the existing per-page search/filter (via context or URL params) or mark it visually as "coming soon" so users aren't confused by a dead input.
2. **Stale date on long-lived tabs** — `today` in `TopBar` is memoized with `[]`, so it never updates after mount. Use an interval or recalculate on visibility change.
3. **In-process cache is per-instance** — Vercel may spawn many instances under load; each cold instance triggers an independent feed fetch. For low-traffic deploys this is fine, but under a burst it multiplies upstream requests. Document or accept this trade-off.
4. **`inFlight` race on cache invalidation** — if a fetch is slow enough that `CACHE_TTL_MS` expires while it's still in-flight, a second request will see `cache` as stale AND `inFlight` as non-null and await the existing promise, which is correct. But if the first fetch fails (returns `[]`), the empty result is served to the second caller as well, and no retry happens until `inFlight` is nulled. The window is small, but worth a comment.

## In-process live cache and the serverless model

The `lib/news/live-cache.ts` module holds a module-scope `cache` variable shared for the lifetime of a single Lambda/Edge instance (5-min TTL). A second variable, `inFlight`, de-duplicates concurrent fetches within the same request burst.

Because the cache is only written when `articles.length > 0`, a failed fetch leaves `cache` as `null` (or previously stale). The next request sees stale cache and triggers a fresh fetch — correct degradation. However, any caller that attached to the in-flight promise receives the empty array from the failed attempt with no retry until the next request arrives after `inFlight` is cleared.

The per-instance isolation means N cold starts within a TTL window produce N independent feed fetches. For a low-traffic dashboard this is acceptable; for a high-traffic deploy it could spike Google News request volume.

## Google News RSS source strategy

The `parseGoogleNewsTitle` function strips the trailing ` - SourceName` that Google News prepends. It avoids mangling legitimate headline dashes by checking that the trailing segment is ≤ 60 chars. This heuristic could occasionally mis-strip a headline that ends with ` - Some Long Phrase` — the risk is cosmetic.

Unreliable feeds (Reuters agency, Bloomberg, FT) are removed with a comment explaining why.

## Route handler cascade (news, graph, analysis)

All three API routes now follow the same live-first pattern:

```
request → getCachedLiveNews() → [live articles]
        ↓ (empty)
        getArticles() from /tmp → [cached articles]
        ↓ (empty)
        mockArticles / mockDailySummary → [sample]
```

Search and date filters in `app/api/news/route.ts` now operate in-memory against the fetched article set rather than calling the store-backed `searchArticles` / `getArticlesByDate`. This ensures filters work uniformly for all data sources but means a search against 180+ articles happens on every filtered request — negligible at this scale, but worth noting the shift from indexed-store to brute-force in-memory.

## Top-bar search is non-functional

`TopBar.tsx` renders:

```tsx
<input
  type="text"
  placeholder="Search here..."
  aria-label="Search"
  className="..."
/>
```

There is no `value`, no `onChange`, no state, no dispatch. Each sub-page (News, Predictions) has its own local search state. The top-bar search would need to either push a query param to the URL (for cross-page search) or be scoped to the current page via context.

## `today` memo has no revalidation

```tsx
const today = useMemo(
  () =>
    new Date().toLocaleDateString("en-US", {
      weekday: "long",
      day: "2-digit",
      month: "short",
    }),
  []
);
```

The empty dep array means `today` is calculated once on mount and never updated. If the user keeps the tab open past midnight (common for a dashboards-on-a-wall scenario), the displayed date becomes stale. Fix: recompute on a 60-second interval or `visibilitychange` event.
