# QuantFeed — v3 final review

A full-stack Next.js 14 platform aggregating Indian and international economic news via RSS, summarizing with OpenAI, visualizing relationships as a force-directed graph, and simulating micro-to-macro economic pathways. All seven v1 issues and all three v2 issues have been addressed. The codebase is production-ready for Vercel deployment with appropriate graceful degradation.

Watch for: the remaining `eslint-disable-next-line no-undef` on `require("rss-parser")` in `fetcher.ts` is a legitimate workaround for a CommonJS-only package — not a masking suppression (confirmed); `/tmp` persistence is ephemeral across cold starts, so the cron pipeline's data survives only within a single warm invocation window — acceptable for an MVP but worth noting in documentation (confirmed).

**Verdict**: APPROVED

## High-level view

The PathwaySimulator infinite-loop fix uses `useRef` to hold `selectedPathway` without adding it to the `useCallback` dependency array. The `runSimulation` callback depends only on `activeInputs` and `simulate` (both stable references), and the `useEffect` includes a 500ms debounce with proper cleanup. No dependency cycle remains.

The `/api/analysis/simulate` endpoint implements an in-memory sliding-window rate limiter (20 requests per minute per IP, keyed off `x-forwarded-for`). Per-instance isolation on Vercel means the effective global limit is higher than 20/min under horizontal scaling, but it prevents a single client from hammering the endpoint.

The store layer writes to `/tmp/quant-feed-data` and reads with a two-tier fallback (`/tmp` first, then bundled `data/`). `saveEdges` now deduplicates by source+target pair. `batchSummarize` processes in batches of 5 sequentially. Both the cron and news-fetch endpoints use fail-closed auth. The NetworkGraph resolves node details from `graphData.nodes` rather than from the mock import.

## PathwaySimulator dependency cycle resolution

The ref pattern avoids the cycle that previously caused infinite re-renders:

```typescript
const selectedRef = useRef(selectedPathway);
selectedRef.current = selectedPathway;

const runSimulation = useCallback(async () => {
  const articleIds = Array.from(activeInputs);
  if (articleIds.length === 0) return;
  const result = await simulate(articleIds);
  setSimulatedPathways(result);
  const current = selectedRef.current;
  if (current) {
    const updated = result.find((p) => p.id === current.id);
    setSelectedPathway(updated || result[0] || null);
  }
}, [activeInputs, simulate]);
```

`simulate` comes from `useSimulation` (stable function reference), and `activeInputs` only changes on user toggle, so the callback identity is stable between renders.

## Rate limiting implementation

```typescript
const RATE_LIMIT_WINDOW_MS = 60 * 1000;
const RATE_LIMIT_MAX = 20;
const requestCounts = new Map<string, { count: number; windowStart: number }>();

function isRateLimited(ip: string): boolean {
  const now = Date.now();
  const entry = requestCounts.get(ip);
  if (!entry || now - entry.windowStart > RATE_LIMIT_WINDOW_MS) {
    requestCounts.set(ip, { count: 1, windowStart: now });
    return false;
  }
  entry.count++;
  return entry.count > RATE_LIMIT_MAX;
}
```

The map lives in module scope, persisting across requests within a warm instance. Input validation rejects empty or non-array `articleIds` with a 400 before reaching the OpenAI call path.
