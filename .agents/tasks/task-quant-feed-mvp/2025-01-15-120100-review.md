# Fix commit: addressing production-readiness review findings (v2)

This commit resolves all seven issues from the v1 review: the filesystem store now writes to `/tmp`, both authenticated endpoints deny access when `CRON_SECRET` is unset, the network graph resolves node details from the graph data rather than mock imports, the pathway simulator calls the simulation API via the `useSimulation` hook, OpenAI calls are batched in groups of five, and edges are deduplicated on save.

Watch for: the `PathwaySimulator` has a `useCallback` that captures `selectedPathway` in its closure, creating an infinite re-render loop when simulation results arrive (confirmed); the `/api/analysis/simulate` endpoint is unauthenticated, letting any client trigger OpenAI pathway analysis without credentials (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The auth fixes follow the correct fail-closed pattern: both `/api/cron` and `/api/news/fetch` now deny when `CRON_SECRET` is absent. However, the simulation endpoint (`/api/analysis/simulate`) was not included in this hardening pass, leaving one unauthenticated path into OpenAI calls from the public internet.

The `PathwaySimulator` wires up the simulation API correctly in concept, but the `useCallback` for `runSimulation` depends on `selectedPathway`, and `runSimulation` itself updates `selectedPathway` — creating a dependency cycle. Every simulation response triggers a state change, which recreates the callback, which triggers the `useEffect`, which calls `runSimulation` again. The `eslint-disable` comment masks the lint warning that would have flagged this.

## PathwaySimulator re-render cycle

The component defines:

```typescript
const runSimulation = useCallback(async () => {
  const articleIds = Array.from(activeInputs);
  if (articleIds.length === 0) return;
  const result = await simulate(articleIds);
  setSimulatedPathways(result);
  if (selectedPathway) {
    const updated = result.find((p) => p.id === selectedPathway.id);
    if (updated) setSelectedPathway(updated);
    else if (result.length > 0) setSelectedPathway(result[0]);
  }
}, [activeInputs, simulate, selectedPathway]);
```

The dependency array includes `selectedPathway`. When `setSelectedPathway(updated)` fires, it changes `selectedPathway`, which recreates `runSimulation`. The `useEffect` lists only `[activeInputs]` with the lint rule suppressed, so in the current code the stale callback reference means `selectedPathway` is captured from a previous render inside the effect — the loop manifests as an unbounded sequence of API calls whenever React re-renders the component due to the callback identity changing (e.g., strict mode double-mount, or when `simulate` returns a new function reference from `useSimulation`).

The fix is to decouple the "update which pathway is selected" logic from the simulation fetch. Store the current selection in a ref, read it after the API response, and only call `setSelectedPathway` without including it in the callback's closure:

```typescript
const selectedRef = useRef(selectedPathway);
selectedRef.current = selectedPathway;

const runSimulation = useCallback(async () => {
  const articleIds = Array.from(activeInputs);
  if (articleIds.length === 0) return;
  const result = await simulate(articleIds);
  setSimulatedPathways(result);
  const current = selectedRef.current;
  if (current) {
    const updated = result.find((p) => p.id === current.id);
    setSelectedPathway(updated || result[0] || null);
  }
}, [activeInputs, simulate]);
```

## Unauthenticated simulation endpoint

The cron and fetch endpoints received auth guards:

```typescript
const secret = process.env.CRON_SECRET;
if (!secret || authHeader !== `Bearer ${secret}`) {
  return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
}
```

The simulate endpoint at `/api/analysis/simulate` has no equivalent check. It accepts a POST with `{ articleIds: [...] }` and calls `analyzePathways`, which invokes `gpt-3.5-turbo` when `OPENAI_API_KEY` is set. Without auth, any HTTP client can trigger OpenAI billing. The client-side `useSimulation` hook doesn't send an auth header either, so adding server-side auth here also requires updating the hook — or treating this as a deliberately public feature with rate limiting to cap cost exposure.
