## High-level view

`pingBackendHealthy()` is an 800ms `AbortController`-bounded GET on `/health` that returns `false` on any non-2xx, timeout, network error, or when `BACKEND_URL` is unset, and never throws. The proxy branch is now `isBackendEnabled() && (await pingBackendHealthy())`, so the `BACKEND_URL`-unset deployment still short-circuits before any network call, and a reachable-but-slow backend costs at most ~800ms instead of the full 4s graph timeout before falling back.

The sentiment asymmetry is resolved by mirroring, not removal. Both `graph_service.filter_articles` and the new block in `app/api/graph/route.ts` derive sentiment with identical thresholds (`>=7` positive, `<=3` negative, else neutral), and a missing score resolves to `neutral` on both sides. The entity filter remains backend-only and silently ignored on the fallback path — a residual asymmetry, now documented rather than fixed.

`parse_published_at` handles the `Z` suffix, treats naive input as UTC, and falls back to `now(UTC)` only on genuinely unparseable input, so it does not corrupt valid ISO timestamps. This makes the write side symmetric with the read side's `datetime`-emitting shape and the `DateTime(timezone=True)` column.

The offline backfill gap is closed with a deterministic, topically-clustered seed set that produces real entity-overlap edges, wired via both a `--seed` flag and an auto-fallback when a live fetch returns `[]`. Commit granularity is now run-level: `PostgresRelationalStore` gained an `autocommit` flag defaulting to `True` (preserving single-write behavior), and the backfill runs with `autocommit=False` and commits once.

Neo4j `RELATES_TO` stays write-only; the `graph_service` docstring now states the read path is authoritatively Postgres-only and that a failed Neo4j upsert cannot cause read-visible divergence — the latent-divergence risk from v1 is defused because there is intentionally no reader. The live integration round-trip remains a managed-cloud follow-up given the sandbox container-runtime constraint; the highest-risk piece of that gap (string→datetime coercion) is now covered by unit tests instead.

### Health gate wiring and the unchanged disabled path

`pingBackendHealthy()` opens a fresh `AbortController` on an 800ms timer against `{base}/health`, returns `res.ok`, and returns `false` on abort, network error, bad response, or a `null` base. The proxy condition became `if (isBackendEnabled() && (await pingBackendHealthy()))`. Short-circuit evaluation means the `BACKEND_URL`-unset deployment never issues the health request, so that path is byte-for-byte the pre-Step-1 behavior. A backend that is up but slow now fails the 800ms health budget and drops to the live-fetch path rather than paying the 4s graph timeout on every request.

The client documents one accepted looseness: `/health` returns 200 even when a datastore is "degraded", so a 2xx health response proceeds to the proxy and the graph call's own null/empty fallback covers the degraded case — the health gate is a latency bound, not a correctness gate.

### Sentiment derivation is now symmetric

```
BACKEND_URL set:    filter_articles()            score = article.economic_impact_score  (float, default 5.0)
BACKEND_URL unset:  route.ts sentiment filter    score = node.economicImpactScore ?? node.val ?? 5
                    both:  >=7 positive / <=3 negative / else neutral
```

The frontend filter runs after `enrichNodes`, so `economicImpactScore` is populated on the nodes it inspects, and its link-pruning matches the adjacent category and date filters. The backend's `ArticleIn.economic_impact_score` is a non-nullable `float` defaulting to `5.0`, so `score >= 7` cannot hit `None` and a missing/default score maps to `neutral` on both sides. The semantic overload flagged in v1 (economic impact is not sentiment) persists by design and is now documented as a Step-1 approximation in `graph_service` with a pointer to the frontend mirror. The entity filter remains backend-only: `?entity=` narrows results with `BACKEND_URL` set and is silently ignored on the fallback path — documented, but still a behavioral difference between the two deployment states.

### `parse_published_at` correctness

```python
text = (value or "").strip()
if text.endswith("Z"):
    text = text[:-1] + "+00:00"
try:
    parsed = datetime.fromisoformat(text)
except ValueError:
    return datetime.now(UTC)
return parsed if parsed.tzinfo is not None else parsed.replace(tzinfo=UTC)
```

Valid aware ISO strings pass through unchanged; the `Z` suffix is normalized to an explicit offset before parsing; a naive value is stamped UTC rather than handed to the aware column where it would raise or silently localize; the `now(UTC)` fallback fires only on genuinely unparseable input, so valid timestamps are never silently corrupted. Tests cover the aware, `Z`-suffix, naive, and invalid cases plus the end-to-end `article_row` shape.

### Offline seed set and commit batching

`seed.py` returns six deterministic, topically-clustered articles (RBI/inflation, markets/Fed, oil, trade) with stable ids and `is_live_data=False`, anchored to an injectable `now`. The clustering is deliberate so the pipeline emits real entity-overlap and semantic edges rather than isolated nodes — `test_seed_backfill_produces_related_graph_offline` asserts `result.edges >= 1`. Backfill uses the seed set both explicitly (`--seed`) and as an auto-fallback when `fetch_live_news()` returns `[]`, closing the "truly offline yields empty graph" gap without weakening the live path.

`_sync()` commits when `autocommit=True` (default, preserving prior per-write behavior for single-write callers) and only `flush()`es when `False` (assigning autoincrement ids inside one transaction); the backfill constructs the store with `autocommit=False` and calls `commit()` once after `run(...)`. The natural-key upserts stay idempotent either way. The `commit()` sits before the `finally` that closes the session, so a successful run commits and a failure closes without committing.

### Justified items and their residuals

Neo4j `RELATES_TO` remains dual-written and unread. The remediation adds no Neo4j read path; instead the `graph_service` docstring states the read path is Postgres-only, that the Neo4j write is forward-investment for a later Graph-RAG step, and that because nothing reads Neo4j edges a Neo4j upsert failing after a Postgres commit cannot produce a read-visible divergence. The v1 divergence risk was "silent drift with no reader to notice"; the disposition is "there is intentionally no reader, and Postgres is authoritative."

The live compose→alembic→backfill→serve round-trip stays unexercised due to the accepted sandbox container-runtime constraint. The string→`DateTime` coercion is no longer part of that gap — it is now handled explicitly and unit-tested — so the residual is the driver-level `/health` pings and idempotency-under-real-constraints, tracked as a managed-cloud follow-up.
