# Predictions expiry, correlations panel, and animated graph rendering — freshness follow-up (v2)

The v1 pass returned NEEDS_CHANGES with seven issues; commit a387b32 addresses all seven. Predictions past their target date are now downgraded to `expired` both in the mock data and at request time via `applyPredictionExpiry`, the predictions page gains an Expired filter/stat, a per-card recency indicator, and a `DataSourceBadge`. The daily summary is pinned to a fixed 2024-12-15 date instead of `todayStr()`, and analysis threads `dataSource` through to a badge. The topic-correlation engine now has a real consumer — a "Trending Threads" panel on the network page — and the relevance score consumes real per-cluster velocity instead of a tag-count proxy. The dead pulse loop now drives ring scale/opacity, and labels start hidden and reveal on zoom-in.

**Watch for:** the per-frame animation loop now runs a full `scene.traverse()` every frame and allocates a fresh `THREE.Vector3` per label per frame — fine at the ~22-node sample scale but a GC-pressure risk if live data grows the graph (possible). Separately, the user explicitly asked to see "the image that is related to it" when zooming a node; the detail panel renders headline, summary, and a Visit Article link but never renders `imageUrl`, and `mockNodes` doesn't even populate that field — a still-unaddressed part of the original request (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

All seven v1 issues are resolved. Predictions expiry is enforced in two places — the mock data statuses were corrected and the route applies `applyPredictionExpiry` on every response — so a past-dated forecast can never read as an active bet even if live data reintroduces one. The `Prediction.status` union and the page's `statusConfig` both gained `expired`.

The correlation engine finally has a UI. The `TopicCorrelationsPanel` reads `graphData.correlations` and renders clusters with keywords and a velocity meter; its field names match the `TopicCorrelation` type. Because all mock dates are December 2024, `changeVelocity` computes to 0 for sample data, so the meter reads 0% until real live articles arrive — the "distinguish old from new" signal stays flat on the deployed sample.

Relevance scoring now uses real topic velocity: the news route builds an articleId→velocity map from `buildTopicCorrelations` and passes each article's cluster velocity into `computeRelevanceScore`. Provenance labeling is also corrected — store-backed search/date hits pass `false` for the request-level live flag, and `scoreArticles` preserves any per-article `isLiveData` before falling back.

The graph render loop is now live: it drives `pulseRing` scale/opacity from the pulse phase and toggles `textLabel` visibility by camera distance (<150 units), with labels starting hidden. Two follow-on concerns remain: the loop's per-frame full-scene traversal with per-node Vector3 allocation is a latent performance cost at scale, and the node detail panel still omits the related image the user asked for.

<summary>Details</summary>

### Predictions expiry is enforced at the source and per request

`applyPredictionExpiry` downgrades any `active` prediction whose `targetDate` is before `now` to `expired`, leaving resolved (`correct`/`incorrect`) and already-`expired` entries untouched. The route calls it on both the store-backed and mock branches and in the catch fallback, so the guarantee holds regardless of data source. The four mock predictions with past target dates were also corrected to `expired` at rest, and `Prediction.status` and the page's `statusConfig` both carry the `expired` case, so the Expired filter tab and stat card render without a type or lookup gap. The per-card recency chip reads "Target {relative}" for open windows and "Window closed {relative}" once past — the stale-active problem the user pointed at is closed on this surface.

### Relevance scoring now consumes real cluster velocity

`buildVelocityMap` runs `buildTopicCorrelations` and maps each articleId to the max `changeVelocity` across the clusters it belongs to; `scoreArticles` passes `velocityMap.get(article.id) ?? 0` into `computeRelevanceScore`, replacing the `tags.length / 6` proxy the v1 review flagged. `computeRelevanceScore` clamps the passed velocity and only falls back to the tag proxy when `topicVelocity` is `undefined` — which the news route never leaves undefined, since uncorrelated articles get an explicit 0. An article on a fast-moving thread now outranks a static one with the same tag count, which is what the 0.2 velocity weight was supposed to buy.

### Provenance flag no longer drifts on filtered paths

The v1 drift — cached store hits inheriting the outer request's `live` flag — is fixed. The `search` and `date` store branches call `scoreArticles(results, false)`, and `scoreArticles` sets `isLiveData: article.isLiveData ?? liveThisRequest`, so an article's own provenance wins and cached hits are never relabeled live.

### Graph render loop drives rings and label LOD

```
scene.traverse((obj) => {
  if (obj.name === "pulseRing") {
    obj.scale.set(pulseScale, pulseScale, pulseScale);
    if (obj.material) obj.material.opacity = pulseOpacity;
  } else if (obj.name === "textLabel") {
    const worldPos = new THREE.Vector3();
    obj.getWorldPosition(worldPos);
    obj.visible = camera.position.distanceTo(worldPos) < LABEL_VISIBLE_DISTANCE;
  }
});
```

The pulse phase feeds `pulseScale` (0.85–1.15) and `pulseOpacity` (0.35–0.75) into every `pulseRing`, and the ring material is `transparent: true`, so fresh-node rings animate. Labels are built with `sprite.visible = false` and revealed only when the camera is within 150 units, implementing the FEAT-002 zoom-in behavior the v1 review said was missing.

The cost is that this traversal walks the entire scene graph every frame and constructs a new `THREE.Vector3` for each `textLabel` on each pass. At ~22 nodes it is negligible, but the allocation is inside the hot path and the traversal is O(scene) per frame; if live data pushes the node count up, this becomes measurable GC churn. Hoisting a single reusable Vector3 above the loop and caching the ring/label object lists at graph-build time would remove both the per-frame allocation and the repeated full traversal.

### Correlation panel is wired but reads flat on sample data

`TopicCorrelationsPanel` consumes `graphData.correlations`, sorts by `changeVelocity`, and renders the top six clusters with a keyword set and a velocity meter, mounted on the network page when `correlations.length > 0`. The clustering produces non-empty clusters for the mock articles (they share keywords), so the panel appears — but `computeChangeVelocity` measures the share of a cluster published in the last 24–48h relative to `Date.now()`, and every mock article is dated December 2024, so velocity is uniformly 0 and every meter reads 0%. The capability is now visible, but on the deployed sample it demonstrates no movement; a few recent-dated sample articles would let the feature show its intended signal.

### Article image still missing from the node panel

The detail panel surfaces the headline, source, freshness, summary, impact, tags, related-article chips, and a Visit Article anchor (`target="_blank"`, `rel="noopener noreferrer"`) — covering most of the user's zoom-in ask. It does not render `imageUrl`, and `mockNodes` maps `url` but omits `imageUrl` entirely, so even the field is empty for sample data. The user's request to see "the image that is related to it" on zoom is the one part of the original instruction still not delivered.
