# Node image on zoom, cached render-loop, and demonstrable topic velocity — freshness follow-up (v3)

The v2 pass returned NEEDS_CHANGES with three issues; commits 065f3fc and 8d1d00b resolve all three. The node detail panel now renders the related article image with a graceful fallback, `mockNodes` populate `imageUrl` from a category placeholder map, and `imageError` resets on each node click. The per-frame animation loop no longer walks the scene graph or allocates per frame — ring and label object references are cached during node construction and a single reusable `THREE.Vector3` is hoisted out of the loop. Four recent-dated sample articles (art-23..art-26, `isLiveData: false`) plus eight connecting edges give the Trending Threads velocity meter a non-zero signal on the deployed sample.

**Watch for:** the graph route re-writes every node's `imageUrl` from its own placeholder map, silently overriding the one `mock-data.ts` sets — two sources of truth for the same field that will drift if either changes (confirmed, minor).

**Verdict**: APPROVED

## High-level view

All three v2 issues are resolved and the build passes with only the two documented benign warnings (`no-img-element` on the intentional `onError`-capable `<img>`, `exhaustive-deps` on the intentional cache-reset `useMemo`).

The node zoom-in now delivers the last unmet part of the original request. `EconomicNode` carries an `imageUrl` field, `mockNodes` populate it from a per-category placeholder map, and the detail panel renders `<img>` with an `onError` handler that falls back to the category gradient. `imageError` resets on every node click so a prior failure doesn't suppress the next node's image. Headline, source, freshness, summary, tags, related-article chips, and the Visit Article link were already in place, so the panel now covers the full "see the related news, headline, image, and link out" ask.

The render loop's performance concern is gone. Ring meshes and label sprites are pushed into `pulseRingsRef`/`textLabelsRef` as they are built in `nodeThreeObject`, and the loop iterates those arrays instead of calling `scene.traverse()` every frame; the label distance check reuses one hoisted `Vector3` instead of allocating per label per frame. A reset `useMemo` clears both caches before each rebuild, keyed to the same values that force ForceGraph3D to rebuild node objects.

The topic-velocity signal is now demonstrable on sample data. Four recent-dated articles share keywords with historical clusters (RBI/inflation, Sensex/FII, semiconductor/manufacturing, Fed/rupee) and carry timestamps 6–40h old, so `computeChangeVelocity` produces non-zero values and the Trending Threads meters move. They stay marked `isLiveData: false`, so provenance honesty is preserved. The correlation algorithm itself (Jaccard fingerprint clustering via union-find, recency-weighted velocity, velocity feeding relevance ranking) is unchanged from v2 and continues to satisfy the "distinguish old from new / latest gets preference" requirement.

### Duplicate imageUrl assignment between mock data and the graph route

`mockNodes` map each article's category through `categoryPlaceholderImages` to a 400x200 placeholder, but the graph route (`app/api/graph/route.ts`) rebuilds every node with its own `categoryPlaceholders` map (120x80 variants), so the `mock-data.ts` value only survives when the panel reads `mockGraphData` directly and the route value wins for API-served data. The same field is now assigned in two places with different dimensions — no user-visible bug today, but a consolidation target so the two maps can't drift.

### Render loop no longer traverses the scene or allocates per frame

The v2 loop ran `scene.traverse()` every frame and built a fresh `THREE.Vector3` per label. Both are gone:

```
const rings = pulseRingsRef.current;
for (let i = 0; i < rings.length; i++) {
  rings[i].scale.set(pulseScale, pulseScale, pulseScale);
  const mat = rings[i].material as THREE.Material & { opacity: number };
  if (mat) mat.opacity = pulseOpacity;
}
const worldPos = reusableWorldPos.current;
for (let i = 0; i < labels.length; i++) {
  labels[i].getWorldPosition(worldPos);
  labels[i].visible = camera.position.distanceTo(worldPos) < LABEL_VISIBLE_DISTANCE;
}
```

Rings and sprites are collected into `pulseRingsRef`/`textLabelsRef` during `nodeThreeObject`, and `reusableWorldPos` is a ref constructed once. The per-frame cost is now O(rings + labels) with zero allocation, so the loop scales with visible node count rather than total scene size.

Cache correctness rests on the reset `useMemo` (`pulseRingsRef.current = []; textLabelsRef.current = []`) firing before each rebuild. Its deps are `selectedNode`, `connectedNodeIds`, and `filteredData` — the first two also drive `nodeThreeObject`'s identity (forcing ForceGraph3D to rebuild every node), and `filteredData` is the `graphData` prop (a category toggle rebuilds too). Every case that clears the cache is immediately followed by a full rebuild that repopulates it, so the arrays never hold stale references across a frame. The latent risk is maintenance: adding a dependency to `nodeThreeObject` without also adding it to the reset `useMemo` would leave the caches pointing at discarded meshes.

### Topic velocity is demonstrable on sample data without faking provenance

Articles art-23..art-26 carry `publishedAt` timestamps computed from `Date.now()` (6h/14h/30h/40h ago) and share keyword fingerprints with existing historical clusters, so union-find groups them and `computeChangeVelocity` — which weights the 24h article share at 0.6 and the 48h share at 0.4 — returns non-zero for those clusters, replacing the flat 0% v2 observed. They stay `isLiveData: false`, and the eight new edges wire them to their historical counterparts so they cluster rather than floating as isolated nodes.

The correlation machinery flows into ranking: per-cluster velocity feeds `computeRelevanceScore` at weight 0.2 alongside freshness (0.5) and impact (0.3), and freshness uses a 12-hour half-life exponential decay, so newer articles rank strictly higher at equal impact/velocity — the "latest news gets more preferability" requirement.
