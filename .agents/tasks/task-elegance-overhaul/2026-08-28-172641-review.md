# Freshness scoring, topic correlation, and 3D graph interaction overhaul for QuantFeed

This change tackles the core complaint that the site presents stale mock content as fresh. It removes the `daysAgo()` trick that rewrote mock publish times to "now", pins mock articles to fixed December 2024 dates, and layers an exponential-decay freshness score (12h half-life) plus a combined relevance score over the news pipeline so recent, high-impact articles sort to the top. A new topic-correlation engine clusters articles by keyword Jaccard similarity and computes a change-velocity signal. The 3D network gets hover tooltips, an enriched click panel with a "Visit Article" link, edge highlighting, and freshness-driven node glow. A broad visual pass (Inter font, glass-premium, shimmer skeletons) rounds it out.

**Watch for:** the predictions surface — the exact place the user pointed at when they said "old probabilities" — was not touched, so it still shows past-dated "active" predictions with static confidence and no sample-data indicator (confirmed). The daily summary still stamps itself with today's date via `todayStr()`, reintroducing the "old data looks fresh" problem on the analysis surface (confirmed). The 3D pulse animation loop runs every frame but its output is never consumed, so fresh-node rings are static (confirmed), and node text labels render at every zoom level rather than on zoom-in as specified (likely).

**Verdict**: NEEDS_CHANGES

## High-level view

The freshness story is now honest for the news list and graph: mock data carries real historical dates and `isLiveData: false`, every article gets a freshness and relevance score, the default sort is relevance-descending, and `dataSource` is threaded from both API routes through the hooks to a visible badge on the dashboard, news, and network pages.

The predictions page is the conspicuous gap. It was the most literal reading of the user's "old probabilities" complaint, but the predictions route, mock predictions, and page received no freshness treatment. Several predictions have target dates already in the past while still marked `active`, confidence values are static, and there is no `DataSourceBadge`. The daily summary has a subtler version of the same problem: its `date` and `id` come from `todayStr()`, so sample analysis always reads as today's.

The correlation engine is self-contained union-find clustering over keyword fingerprints at a 0.3 Jaccard threshold with a recency-weighted velocity metric. It's wired into the graph response as `correlations`, but nothing in the UI consumes that array, and because mock dates are all December 2024 the velocity computes to zero for sample data — the "distinguish change between old and new" capability exists in the API but is invisible to the user.

The 3D interaction upgrades largely land, but two rendering intentions didn't make it through: the per-frame pulse phase is computed but never applied to the ring, and labels are always visible instead of appearing on zoom-in — so the graph is more static and more cluttered than the feature spec describes.

<summary>Details</summary>

### News route dataSource drift on filtered paths

The `search` and `date` filters, when their store-backed branch returns hits, re-map those results and stamp `isLiveData: dataSource === "live"`. Those store hits are cached articles independent of whether the outer flow performed a live fetch this request, so a cached search result can be tagged as live data (confirmed by reading the `searchArticles`/`getArticlesByDate` re-map). The freshness score stays correct since it derives from `publishedAt`; only the live/cached provenance flag drifts.

### The relevance score's velocity factor is a proxy, not the real signal

`computeRelevanceScore` blends freshness (0.5), impact (0.3), and a "topic velocity bonus" (0.2). The velocity term defaults to `Math.min(1, tags.length / 6)` — article tag count, not the change velocity the topic tracker computes. The function accepts an optional `topicVelocity` argument but the news route never passes it, so the 0.2 weight rewards articles for having more tags. The "recency-weighted correlation" the user asked for isn't feeding the ranking; an article on a fast-moving thread ranks no higher than a static one with the same tag count.

### Topic correlation engine: no consumer, zero velocity on sample data

`buildTopicCorrelations` runs union-find clustering at a 0.3 Jaccard threshold and emits clusters of 2+ articles with keywords, member IDs, velocity, and latest date, sorted by velocity; the pairwise comparison is O(n²), fine at this article volume.

Two things blunt its value. `computeChangeVelocity` measures the share of cluster articles published in the last 24h/48h relative to `Date.now()` — but every mock article is dated December 2024, so for sample data velocity is uniformly 0. The capability only produces a non-zero signal against genuinely live data, which the deployed app rarely has. And the `correlations` array is returned in the graph response and typed through `GraphResponse`, but no component reads it, so from the user's seat the correlation feature is invisible.

### 3D graph: dead pulse loop and always-on labels

Tooltips, the detail panel, the Visit Article anchor (`target="_blank"`, `rel="noopener noreferrer"`), related-article chips, and reactive edge highlight/dim via `linkColor`/`linkWidth` are all present. The gaps are in node rendering:

```
useEffect(() => {
  const animate = () => {
    pulsePhaseRef.current += 0.03;      // incremented every frame...
    animationFrameRef.current = requestAnimationFrame(animate);
  };
  ...
}, []);
```

`pulsePhaseRef` is advanced every frame but never read — not in `nodeThreeObject`, not in any per-frame scene update. The ring tagged `pulseRing` for fresh articles (`freshnessScore > 0.7`) is built once and never animated, so the "pulsing animation for fresh articles" is a static ring and the loop is pure overhead.

Separately, the text-label sprite carries the comment `// Start visible - ForceGraph3D manages LOD internally`, but ForceGraph3D does not apply level-of-detail culling to sprites inside a custom `nodeThreeObject` group — the sprite stays visible at every camera distance. FEAT-002 called for labels that appear when camera distance is under 150 units; as built, all labels render always, cluttering the scene at wide zoom (likely — traced through the render path, not runtime-confirmed).

### Data-source badge coverage is asymmetric

The badge is wired into the dashboard, news, and network pages but absent from the predictions page — the one surface the user explicitly called out for stale content. Combined with the untouched predictions route and the `todayStr()`-dated daily summary, the "is this real or sample" signal is present exactly where the freshness work was done and missing exactly where the original complaint pointed.

### Predictions: the unaddressed complaint

The predictions route, `mockPredictions`, and predictions page received no freshness treatment (confirmed — the route is byte-identical to the base branch and the page diff is purely visual). Several mock predictions carry target dates already in the past (`pred-1` targets 2025-03-31, `pred-2` 2025-04-30) while still marked `status: "active"` with fixed confidence values. There is no logic to mark a prediction `expired` once its target date passes, no recency indicator, and no `DataSourceBadge`. The user's phrase "showing old probabilities" maps most directly to this surface, and it is the part of the change that did not move.
