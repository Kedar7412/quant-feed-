# Step 2 review fixes: draw-count, cumulative edge diff, O(1) reverse map (v2)

The follow-up commit `989192d` addresses all six issues from the v1 review. The node mesh now draws `count={highWater}` instead of `liveCount`, so a remove-only diff no longer truncates high-index live slots; a slot→id reverse map (`slotIds`) backs new `getIdForSlot`/`getDrawCount` accessors and replaces both per-frame and per-click full-map scans. The ingestion hook now reads the cumulative persisted edge set back from Postgres and publishes it, so the backend producer and the client's full-rewrite consumer finally agree on `updatedEdges` semantics. `InstancedEdges` clamps its draw range to the live edge count every frame, and the predicate's best-effort date/entity handling is documented for product sign-off with no behavior change.

Watch for: nothing blocking. The one residual is that the cumulative-edge wiring in `run_ingestion` (`PostgresReadStore(session).list_edges()`) is only exercised by the pure builder test, not end-to-end — the live Postgres→Redis→WS path remains deferred to the user's infra (confirmed, expected, not a defect). The reverse map, draw-count fix, and edge-rewrite ordering are all verified in code and by revert-sensitive tests.

**Verdict**: APPROVED

## High-level view

`getDrawCount()` returns `highWater`, `InstancedNodes` subscribes to `s.highWater`, and drawing `[0, highWater)` covers every live node while freed slots below the mark stay scale-0. The new regression test removes without re-adding — the case the old suite never produced — and asserts `drawCount == 3 > liveCount == 2` with the top live slot still inside the range. Flipping `getDrawCount` back to `liveCount` fails two tests, so the guard is genuinely revert-sensitive.

Issue #2 is resolved by aligning the producer with the client's full-rewrite contract rather than changing the client. `run_ingestion` reads the full edge set via `PostgresReadStore(session).list_edges()` after persistence and passes it as `cumulative_edges`; the builder emits that set instead of just the run's `scored_edges`. The read is gated on `realtime_enabled` and wrapped so it can never fail ingestion, and the full-rewrite contract is now documented on both the TS and Python `GraphDiff`.

Issues #3/#4 collapse into the `slotIds` reverse map, maintained in lock-step with `nodeSlots` on add, remove, init, and clear. Slot recycling is handled correctly: a removed slot is deleted from the map before it is pushed to the free-list, so a later reuse overwrites it with the new id and no stale slot→id entry survives — verified by a test that removes then re-adds into the same slot.

Issue #5 relies on `applyDiff` synchronously rewriting `edges`/`edgeCount` before returning, plus a per-frame `setDrawRange(0, count*2)` in the same `useFrame` that reads the freshly-rewritten count. A remove-only diff cannot draw a stale segment against a just-freed slot even before the classification effect runs. Issue #6 is a docstring-only change flagging the intentional best-effort behavior.

<summary>Details</summary>

### Draw count now spans sparse slots

The new `REMOVE-ONLY diff` test initializes `a,b,c`, removes `a` alone, and asserts `getDrawCount() == 3`, `getLiveCount() == 2`, `getDrawCount() > getLiveCount()`, and that `c` at slot 2 is inside `[0, drawCount)`. A second case removes `a,b` and asserts the draw count still spans slot 2. Reverting `getDrawCount` to `liveCount` fails both — the truncation the review predicted is exactly what the test now catches, and it exercises the remove-only path the old suite masked by always re-adding.

### Producer and consumer agree on edge-diff semantics

The mismatch was one-sided: the client always treated `updatedEdges` as a full topology replace, but the producer sent only the run's scored edges. The fix keeps the full-rewrite contract and makes the producer honor it. `build_ingestion_diff` takes an optional `cumulative_edges`; when supplied it serializes that set, otherwise it falls back to `result.scored_edges` so the pure builder stays usable in isolation. `run_ingestion` supplies the cumulative set from `PostgresReadStore(session).list_edges()`, which selects every persisted `Edge` and returns `list[ScoredEdge]` — type-compatible with `schema_map.graph_link`. The read-back is inside `if settings.realtime_enabled:` and wrapped in a try/except that logs and continues, so neither the read nor an empty result can fail ingestion.

The revert-sensitive test seeds one run edge (`a1→a2`) plus a pre-existing `a2→a3` in the cumulative list and asserts the diff carries both; if the builder reverted to `result.scored_edges` it would carry only `a1→a2` and fail. The remaining gap is that no test drives `run_ingestion` itself, so the actual `list_edges()` read and its threading into `publish_ingestion_diff` are unverified end-to-end — correctly deferred to a live Postgres/Celery/Redis environment.

### Reverse map is consistent across slot recycling

`slotIds` is written on add, deleted on remove (before the slot is pushed to the free-list), and cleared on `init`/`clearAll`, mirroring every `nodeSlots` mutation. The recycling test removes `b` (asserting `getIdForSlot(1)` becomes undefined), then adds `d`, which reuses slot 1 and makes `getIdForSlot(1) == "d"` — proving no stale entry survives reuse. `GraphLabels` now reads `state.slotIds.get(c.slot)` and `GraphScene.idForSlot` delegates to `getIdForSlot`, and both old full-scan helpers are deleted, so the O(labels × nodes) per-frame cost and the per-click scan are gone.

### One-frame stale edge draw is closed

`applyDiff` rewrites edges last, after removes and adds, so `state.edges`/`state.edgeCount` reflect the final slot map before it returns. `InstancedEdges` reads that fresh `edgeCount` in `useFrame` and now calls `setDrawRange(0, count*2)` on every frame, and `setDrawRange(0, 0)` on the empty-topology branch. The classification effect that also sets the draw range runs after the diff, but the per-frame clamp means the draw range already reflects the post-diff count before the effect fires, so no segment can draw against a recycled slot. `setDrawRange` is a scalar call, introducing no per-frame allocation.
