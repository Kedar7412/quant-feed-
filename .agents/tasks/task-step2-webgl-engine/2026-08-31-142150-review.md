# Custom R3F WebGL graph engine + real-time diffs, feature-flagged (v1)

Step 2 rips out `react-force-graph-3d` and replaces it with a hand-built React Three Fiber engine: one `InstancedMesh` for all nodes driven by a custom GPU shader, a single `LineSegments` edge layer with a flow shader, SDF labels with frustum+distance+importance LOD, a camera rig, and camera-distance cluster impostors. All scene data lives in pre-allocated typed arrays owned by a vanilla Zustand store created outside React; a d3-force-3d Web Worker and an optional WebSocket diff stream mutate those arrays in place and flag dirty slot ranges that `useFrame` pushes to the GPU under `frameloop="demand"`. Slot recycling via a free-list is the declared fix for the prototype's filter-toggle leak. Real-time is layered additively behind `NEXT_PUBLIC_WS_URL` (frontend) and `REALTIME_ENABLED` (backend), with a FastAPI `/ws/graph` gateway applying a server-side per-client predicate over Redis-published diffs.

Watch for: the node mesh draws `count={liveCount}` instances (**confirmed**), which truncates the wrong slots after any remove-only diff because slots are sparse, not compacted — high-index live nodes vanish and empty low-index slots draw. The ingestion diff publishes only the current run's scored edges while the client applies `updatedEdges` as a **full topology replace** (**confirmed** in code; **likely** to wipe the client's edge set in the live loop). Free-list, predicate, backoff, and graceful-fallback paths are otherwise correct and well-tested; scope is clean (no Step 3 auth/billing/Graph-RAG in source).

**Verdict**: NEEDS_CHANGES

## High-level view

The state layer is the heart of the change and it is built the way the spec asked: buffers allocated once at `CAPACITY`, a stable slot per node, a LIFO free-list that recycles removed slots so remove-then-add churn never grows the high-water mark, and a single inclusive dirty range consumed once per frame. The unit tests pin the exact recycled index and prove the high-water mark stays flat across 50 churn cycles.

The render loop honors the "React does not reconcile 3D nodes" rule: `InstancedNodes`/`InstancedEdges`/`GraphLabels`/`ClusterImpostors` each subscribe only to coarse counts and otherwise read the store imperatively inside `useFrame`, with hoisted scratch and no per-frame heap allocation in the hot path. The one defect in this layer is that the instanced node draw count is tied to `liveCount` rather than the high-water mark, which is incorrect precisely because slots are sparse after removals — the same free-list design that fixes the leak breaks this assumption.

Edge topology is applied as a wholesale rewrite of the edge buffer on every diff. That is internally consistent for a full-graph diff, but the ingestion hook emits only the edges scored in that run, so a live diff would collapse the client's edge set to just the latest batch. This is the one place where the backend producer and the frontend consumer disagree on what `updatedEdges` means.

The WebSocket layer degrades cleanly: with the env var unset no socket is constructed and the page renders from `/api/graph` unchanged; ingestion is a no-op when `REALTIME_ENABLED` is false and swallows broker errors when on. The server-side predicate reuses the REST sentiment/category derivations and prunes edges to surviving endpoints, and the filter-update path is proven to take effect without a reconnect.

### Slot lifecycle and the free-list leak fix

The store keeps every per-node attribute in a flat typed array sized to `CAPACITY`, with `nodeSlots` mapping id→slot and a `freeList` stack of recycled indices. `acquireSlot` pops a freed slot first and only advances `highWater` when none are free, returning `-1` at capacity so adds drop-with-warning rather than throw. `applyDiff` removes before it adds so a remove-then-add within one diff reuses the freed slot. The tests assert the exact recycled index (`d` lands in `b`'s old slot 1) and that 50 remove/add cycles leave `highWater` at 2 — a real behavioral test that directly validates the leak fix and would fail if recycling regressed.

### Instanced node draw count is wrong for sparse slots

`InstancedNodes` renders `count={Math.max(liveCount, 0)}`. `InstancedMesh` draws instances `0..count-1`. Because slots are stable and never compacted, live nodes can occupy indices `>= liveCount` after removals:

```
init a,b,c  -> slots a=0 b=1 c=2, liveCount=3, count=3   (draws 0,1,2 ✓)
remove a    -> slot 0 freed, b=1 c=2, liveCount=2, count=2 (draws 0,1)
                             ^ slot 0 empty (scale 0), slot 2 (c) NOT drawn ✗
```

`c` disappears and the empty slot 0 occupies a draw slot. The `graphSocket` diff test removes-and-adds in the same diff (the add refills slot 0 and `count` stays correct), which is why the suite is green — the hole only appears on a remove-only diff, which the tests never produce. `GraphLabels` and `ClusterImpostors` iterate `nodeSlots` directly and are unaffected, making this a nodes-only visual dropout. Fix by driving `count` from `highWater` (all slots below the high-water mark are either live or scale-0 empties, both safe to draw).

### Edge topology: full rewrite vs. partial ingestion diff

`rewriteEdges` sets `edgeCount` from only the edges passed in and treats the diff's `updatedEdges` as the complete topology. `build_ingestion_diff` populates `updated_edges` from `result.scored_edges` — the edges produced by that single ingestion run, not the cumulative graph. A client that loaded the full graph via `/api/graph` and then receives an ingestion diff has its entire edge buffer replaced by just the latest run's edges, dropping everything else. The `GraphDiff` docstring explicitly says "applied as a full rewrite," so the client behavior is intentional; the mismatch is on the producer side. Resolve by publishing the full current edge set from the ingestion hook, or switch the client to a merge/patch semantic. The live ingestion→Redis→WS loop is deferred, so this needs an explicit check in the user's environment.

### Render-loop allocation discipline

The hot paths hold to the zero-per-frame-allocation rule. `InstancedNodes.syncRange` reuses module-scope `Matrix4`/`Vector3`/`Quaternion`/`Color` scratch; `InstancedEdges` mutates pre-allocated geometry attribute arrays in place and only advances a `uTime` uniform per frame; `GraphLabels` uses a fixed pool of 50 `Text` instances plus a `CAPACITY`-sized candidate array grown once, with an in-place partial selection sort for the top-N; `ClusterImpostors` accumulates category centroids into hoisted `Float32Array`s. The dirty-range object from `consumeDirtyRange` is the one intentional per-frame allocation, emitted at most once per frame. Teardown is explicit: each component disposes its own geometry/materials on unmount and `GraphScene` owns and disposes the shared node material.

### Per-frame reverse lookups

`GraphLabels` resolves each visible label's id via `idForSlot`, a full `nodeSlots.forEach` scan, once per label per frame (up to 50 scans/frame). `GraphScene.idForSlot` does the same per click. Both scale with node count; a slot→id reverse map maintained alongside `nodeSlots` removes the scan. The click-path one is negligible; the label one runs every rendered frame and is worth fixing before large graphs.

### Worker layout and the outside-React ownership rule

The store is created via `zustand/vanilla` `createStore` outside the render tree, and the engine/worker/WS client all mutate it imperatively; React components subscribe only through `useStore` selectors for HUD counts and selection. The force sim runs in a module worker (`d3-force-3d`) keyed by stable slot indices, transferring the positions buffer back to avoid a copy, and `onTick` scatters straight into `positions` and widens the dirty window. `forceSimClient` no-ops when `Worker`/`window` are absent (SSR/tests) and tolerates module-worker rejection, so the page renders without a worker. Visibility updates pin filtered-out nodes in place rather than removing them, keeping slot indices stable while they stop influencing the layout.

### Graceful fallback and the WS client

With `NEXT_PUBLIC_WS_URL` unset, `realtimeWsUrl()` is null → `isRealtimeEnabled()` false → the page's realtime effect early-returns and no `GraphSocket` is constructed, so the network page behaves exactly as the REST-only build. `GraphSocket.start` additionally requires a browser `WebSocket` unless a factory is injected, never throws, and every callback swallows errors. On each open it fires `onResync` (re-seeding the store from the last REST graph) then re-subscribes with the current filters; store filter changes forward as deduped `filter-update` messages without reconnecting; reconnects use capped exponential backoff. The tests drive a fake socket and injected scheduler and assert the subscribe payload, diff application, malformed-message tolerance, filter-update forwarding, the exact backoff schedule, and that `stop()` suppresses reconnect — all revert-sensitive.

### Server-side predicate parity with REST

`ClientFilters` normalizes `category`/`sector` (treating `all` as no filter) and derives sentiment from `economic_impact_score` with the same `>=7 / <=3` thresholds as `graph_service`, and `prune_edges` mirrors the REST link-pruning so streamed edges never reference a filtered-out node. `_narrow` always forwards `removedNodes` and drops the diff when it narrows to empty. The receive/forward loops run concurrently so a `filter-update` applies mid-stream; the WS test proves a political diff that would have been dropped under the initial economic filter is delivered after the update, without reconnecting. Entity and date filters are deliberately best-effort on diffs (diff nodes carry no `publishedAt`, and entity match falls back to label/summary/tags), so an entity- or date-scoped client can receive adds it cannot positively exclude until the next REST window — documented in the predicate and worth a product decision.

### Backend publish path and testability

`InMemoryDiffPublisher` fans out to per-subscriber queues and replays its backlog so the subscribe/publish race can't drop a diff in tests; `RedisDiffPublisher` constructs its client lazily so importing the module never needs a broker. `publish_ingestion_diff` runs after persistence, no-ops when `realtime_enabled` is false, and swallows any exception so realtime can never fail ingestion — both branches are tested (no-op when disabled, silent failure against an unreachable broker). The diff serializes to the exact camelCase `{addedNodes, removedNodes, updatedEdges}` contract, asserted on both the gateway output and the ingestion builder.

### Scope discipline

Grep for Step 3 concerns (auth/login/jwt/oauth, stripe/billing/subscription, graph-rag) matches only task-plan JSON and doc/comment strings, never source. `react-force-graph-3d` and `components/NetworkGraph` survive only in prior task artifacts under `.agents/tasks/`; the component and dependency are gone from the app.

### Test coverage

Covered and revert-sensitive: free-list slot reuse and flat high-water under churn, capacity drop-without-corruption, dirty-range expansion/consume, edge slot-mapping with dangling-edge skip, selection flag flips, visual-mapping monotonicity, forceSimClient SSR no-op, the canvas-mount object-construction/sync path, the full WS client lifecycle, backoff schedule, server-side predicate drop + filter-update, camelCase contract, and the ingestion publish guards.

Not tested: the remove-only-diff draw-count hole (the suite only ever removes-and-adds together, masking the `count={liveCount}` bug); the ingestion partial-edge-diff wiping client topology (no cumulative-edge assertion); a diff that adds a node at a slot `>= liveCount` asserting it would be drawn; concurrent multi-client narrowing on the gateway. Frame rate, real shader compile/visual correctness, real worker ticks/camera feel, and the live ingestion→Redis→WS loop are correctly deferred to the user's browser+GPU and managed infra.
